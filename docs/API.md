# API

Базовий URL: `http://127.0.0.1:8000`. Усі запити й відповіді в JSON.
Інтерактивна документація (можна пробувати запити): `/docs`.

- `id` — рядок (hex).
- Час `created_at` — UTC у форматі ISO 8601 (`2026-10-17T12:00:00+00:00`). Показувати у локальній зоні має фронтенд.
- Помилка: HTTP-код і `{"detail": "текст помилки українською"}`.
  - `400` — не пройшла валідація (порожнє повідомлення, дубль імені, невідомий учасник…).
  - `422` — неправильна форма запиту (бракує поля).
  - `500` — проблема зі сховищем (наприклад, пошкоджений файл даних).

## Користувачі

| Метод і шлях | Тіло | Відповідь |
|---|---|---|
| `POST /api/users` | `{"username": "alice"}` | `201` `{"id", "username"}` |
| `GET /api/users` | | `[{"id", "username"}]` |

Ім'я: до 32 символів, літери/цифри/`.`/`_`/`-`, унікальне без урахування регістру.
Паролів і токенів поки немає: «вхід» на фронтенді це вибір існуючого користувача.

## Розмови

| Метод і шлях | Тіло | Відповідь |
|---|---|---|
| `POST /api/conversations` | `{"participant_ids": ["id1","id2"], "title": "необов'язково"}` | `201` `{"id", "title", "participants"}` |
| `GET /api/conversations?user_id=<id>` | | `[{"id", "title", "participants"}]` |

Мінімум 2 учасники; 3 і більше це груповий чат. `user_id` необов'язковий: з ним повертаються лише розмови цього користувача.

## Повідомлення

| Метод і шлях | Тіло | Відповідь |
|---|---|---|
| `POST /api/conversations/{id}/messages` | `{"sender_id": "<id>", "text": "привіт"}` | `201` `{"id", "conversation_id", "sender_id", "text", "created_at"}` |
| `GET /api/conversations/{id}/messages` | | масив повідомлень, відсортований за часом |

Текст: не порожній, до 2000 символів (пробіли по краях обрізаються). Відправник має бути учасником розмови.

## Пошук

`GET /api/search?q=привіт&user_id=<id>` повертає масив повідомлень (як вище), що містять `q` без урахування регістру. `user_id` обмежує пошук розмовами цього користувача. Порожній `q` це `400`.

## Живий чат (WebSocket), тимчасово

`/ws/{username}` це старий демо-чат: розсилає текстові рядки всім підключеним і не пов'язаний з історією вище. Поки що для UI використовуйте REST (опитування історії раз на кілька секунд). Інтеграцію WebSocket із сервісом додамо пізніше.

## Дані

Зберігаються у файлі `data/messenger.json` (шлях можна змінити змінною середовища `MESSENGER_DATA`). Файл створюється при першому запуску, запис атомарний.
